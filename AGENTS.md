# AGENTS.md — enso

## Quick start

```sh
# Build & test inside Docker (primary dev workflow)
docker compose build
docker compose run islasgeci make tests
docker compose run islasgeci make coverage

# Acceptance specifications, in the image that carries qed
docker compose --profile develop build develop
docker compose --profile develop run --rm develop make verify
```

## Public interface

The public interface is the `enso` R package: the functions a user reaches with `library(enso)` after installing it. `DOCS.md` lists those functions; this file does not.

Everything else in `R/` is internal, and `NAMESPACE` is generated by roxygen2.

## TDD cycle (encoded in Makefile)

The project uses a strict red/green/refactor cycle via `make`. Each phase applies `styler` formatting, runs tests with `stop_on_failure = TRUE`, then auto-commits:

| Phase | Command | Auto-commits | On failure |
|-------|---------|-------------|------------|
| Red (write failing test) | `make red` | `tests/testthat/*.R` | `git restore .` |
| Green (make pass) | `make green` | `R/*.R` | `git restore .` |
| Refactor | `make refactor` | `R/*.R` + `tests/testthat/*.R` | `git restore .` |

- `make check` — check styler formatting (no auto-fix, used in CI).
- `make format` — auto-format R/ and tests/ with `styler`.
- `make setup` — `clean` + `install` (rebuilds package, regenerates NAMESPACE, runs `devtools::check`).
- `make tests` — run `devtools::test(stop_on_failure = TRUE)`.
- `make verify` — install the package, then `qed verify specs`.

## Architecture

- **Internal functions** in `R/`: `compute_month()`, `compute_year()`, `compute_trimester()`, `wide2long()`, `compute_oni_window()`, `is_consecutive_run()`.
- **Specifications** live in `specs/` as qed TOML, one file per public function; every criterion runs a testthat acceptance file.
- The default branch is `develop`; the repository has no `main`.

## Testing

- **testthat edition 3**, BDD-style with `describe()`/`it()`.
- `tests/testthat/test_acceptance_*.R` hold the acceptance tests and start with `library(enso)`, so they reach only the public interface. `make verify` runs them through qed; `make tests` also picks them up.
- Unit tests cover the internals.
- Test fixtures live in `tests/data/` (`roni_data.csv`).
- Tests read CSVs with `readr::read_csv("/workdir/tests/data/...")` — path is hardcoded for the Docker container.

## Dependencies & toolchain quirks

- Remote dependencies: `IslasGECI/testtools` (installed via `remotes` in `DESCRIPTION`). `tidyverse` brings lubridate, dplyr, and tidyr.
- qed is not an R package: `Dockerfile.dev` builds it from source with Lean, and the `develop` Compose profile keeps that image out of the normal build.
- `Dockerfile.dev` starts FROM `islasgeci/enso:latest`, so `docker compose build` must run before the `develop` profile build.
- `.Rbuildignore` and `.gitignore` are tracked; the build skips `specs/` and `.pipelines/`, so a new top-level path needs an entry there.
- `testthat::test_file()` exits 0 even when a test fails; the criteria pass `stop_on_failure = TRUE` for that reason.
- `Rscript` has no `--expr` option; use `-e`.
- `NAMESPACE` is **generated** by roxygen2 — never edit by hand. Regen with `devtools::document()` (part of `make setup`).
- `man/` directory is generated the same way.
- Coverage uses `covr` package + Codecov (token in `tests/testthat/coverage.R`).
- CI runs inside Docker only: `docker build` → `make check` → `make coverage` → `make mutants` → `bash .pipelines/verify.sh`.
